## 前半 · 先生・ALTのみなさんへ

### 英語の授業に、もうひとつの楽しみ方を

Aomiyalingoは、**『Blue Sky』で出会った英語を、いつもと少し違う形で練習できるアプリ**です。授業の最初のウォームアップにも、単元の復習にも、ちょっと気分を変えたいときにも使えます。教科書と組み合わせながら、その日の授業に合う使い方を選んでください。

収録しているのは、**5年生のUnit 1〜8と、6年生のPre Unit〜Unit 8**。単語や表現に加えて、画像・単語の発音音声・例文を用意しています。画面は最初は日本語ですが、歯車からいつでも英語に切り替えられます。

### 「単語練習」と「単語レース」

| 単語練習 | 単語レース |
| --- | --- |
| 一人ひとりが自分のペースで、短いレッスンに取り組みます。 | 先生の進行に合わせて、みんなでゲームに参加します。 |
| ヒントや復習で、苦手な単語をもう一度練習できます。 | 動物のアバター、連続正解、道具、ライブ順位で盛り上がります。 |
| 先生は回答を見ながら、もう一度扱いたい単語を確認できます。 | 先生は進み具合を見ながら、一時停止や次のコースへの切替ができます。 |

問題は、意味を選ぶ、聞いて選ぶ、文字タイルでつづる、ことばをペアにする、文を並べ替える、穴を埋めるなど。画像を使う問題や、聞いた内容を組み立てたり入力したりする問題もあります。レースは後のコースほど手応えのある活動が加わり、一人ひとりの最近の回答に合わせて支援が変わります。

標準のレースは、**1コース6分、全部で3コース。時間内の問題数に上限はありません。** 出題順は児童ごとに変わります。子どもたちは動物のアバターを選んで「準備完了」を押し、ゲームの説明を読みながら開始を待ちます。参加受付が開いていれば、遅れてしまった子も途中から参加できます。説明画面では、取り組む単元、問題の種類、道具の使い方、教科書を見てもよいことを案内します。

**レースの得点は、授業を楽しくするためのものです。** 正解だけでなく、連続正解や道具も得点に影響します。学習の様子を詳しく見たいときは、ゲームの順位だけで判断せず、回答記録や自力で正解した割合を見てみてください。

### 授業を始めるには

1. このページ上の緑のボタンからアプリを開き、先生用パスワードでログインします。
2. 「単語練習」か「単語レース」を選び、学年と単元を決めます。必要なら、そのモードの中で教材やルールを調整できます。
3. QRコードを見せるか、生徒用リンクを共有します。子どもたちは開いた画面で出席番号を入力します。
4. 先生のタイミングで活動を始めます。一時停止や終了も先生の画面から操作できます。

パソコン・タブレット・スマートフォンなど、インターネットにつながり、対応するブラウザーが使える機器から参加できます。プロジェクトのダウンロードやZIPの解凍は必要ありません。画面をみんなに見せたいときは、普段使っているプロジェクターやテレビへの接続、画面共有を使ってください。

音がすぐに出ないときは、再生ボタンを押すなど、まず画面を一度操作してみてください。ブラウザーの音声設定や使える英語の読み上げ音声は、機器によって異なります。BGMは先生用画面だけで流れ、児童がQRコードから開く画面では流れません。

### クラスに合わせて、少しずつ

選んだモードの中で、単語、例文、問題の設定、ゲームのルールを変更できます。参加受付の管理、新しいレースを準備するためのリセット、回答の確認、成績のCSV保存もできます。削除した記録を戻す操作と、完全に削除する操作は分かれています。

歯車には、表示言語、音、画面表示、ヘルプなどの設定があります。更新確認で新しい版のお知らせを見ることもできます。GitHubに新しいソースがあっても、サーバーの管理者による公開作業が必要な場合があります。

## 後半 · 開発者・保守を引き継ぐ方へ

この節は、元の保守担当者が離れた後も開発・運用を継続できるようにするための技術的な入口です。Release 79の実装と運用上の境界を記載しています。動作を変更する前に、[AGENTS.md](AGENTS.md)、[ARCHITECTURE.md](ARCHITECTURE.md)、[Release 79の技術情報](docs/release-79.md)を確認してください。構成文書の各項目は、そのリリース時点の説明です。過去の測定値やテスト数を、現在の保証として扱わないでください。

### 開発の目的と設計原則

- **先生が進行を管理する：** ルートページで先生を認証し、練習とレースを選択します。児童用リンクは特定のクラスまたはレースを指します。授業開始までの操作を短く保ち、進行権限を先生側に残します。
- **2つのモードの役割を分ける：** 単語練習は学習・復習・診断を支援し、レースは演出と参加意欲を高めます。娯楽用の得点を、説明なく学力評価の指標に変更しないでください。
- **学習処理を重複実装しない：** 両モードは問題の具体化と検証処理を共有します。新しい問題は共有境界に追加し、各モードの既存の送信処理に接続します。
- **教材データを拡張点にする：** 教材設定、例文、編集可能なルールを中心に拡張します。中学校対応は将来の候補であり、実装済みの教材ではありません。
- **保存記録と処理の所有権を維持する：** 認証、リビジョン検証、重複送信への同一結果の返却、保存形式、リクエストの所有権を保持します。構造整理と採点・スキーマ・授業動作の変更を分離します。

### アーキテクチャとソースの入口

JavaScriptのES Modules、ブラウザー画面、Cloudflare WorkerのHTTPアプリケーション、永続D1データベースで構成しています。現在は、インスタンス単位の先生用共通パスワードを使うアプリです。学校別アカウントやテナント分離を備えたプラットフォームではありません。

| [server/classroom/](server/classroom/) | 先生・児童の認証、参加者の識別と復帰、レッスン進行、採点、進捗取得。 |
| [race-server.mjs](race-server.mjs)、[server/race/](server/race/) | レースの組み立て、ルール、永続化、先生・児童の操作、採点。 |

| [public/learning/](public/learning/)、[public/learning/exercises.js](public/learning/exercises.js) | 共有のレッスン・学習診断・問題具体化と検証ロジック。 |

`build.mjs`はブラウザー用スクリプトとCSSをバンドルし、最終的な素材のハッシュをURLに付与して、公開素材を含む`dist/server/index.js`を生成します。一部の語彙カタログは従来のクラシックスクリプト用アダプターを経由します。利用側と保存形式を明示的に移行するまでは、この互換境界を維持してください。生成済みWorkerではなく、元のソースを編集します。

### 正式な状態と並行処理の契約

1. **認証と採点はサーバーが行います。** 先生はサーバーで検証するHttpOnly Cookie、児童の操作は参加に紐づくBearer認証を使用します。出席番号は画面上の識別情報であり、認証用の秘密情報ではありません。QRリンクに含まれるのはルーム識別子で、参加者の認証情報ではありません。
2. **教材は作成時点で固定します。** クラス・レース作成時に選択した教材とルールをスナップショット化します。後から編集した設定で進行中の内容を置き換えてはいけません。従来の教材キー、ルール版、レッスン保存形式を維持します。
3. **更新にはリビジョン検証が必要です。** 複数行にまたがる状態切替・準備完了処理は、compare-and-swap条件と遷移トークンで保護します。条件判定と依存する更新を一体で扱い、無条件更新や別リクエストへの分割を避けてください。
4. **回答送信の所有者を1つにします。** 練習のトランザクション処理とレースの児童コントローラーは、送信時の認証情報と画面世代を保持します。未確認回答の保存、二重送信の抑止、同一回答の安全な再送を維持します。古い定期更新・応答・`finally`処理が新しい画面や別の送信を変更してはいけません。
5. **演出をゲーム状態の根拠にしません。** 道具抽選の演出、音声、祝福、補間表示の時計はサーバーの状態を表示します。演出から加点や回答位置の更新を行いません。一時停止では入力中・送信待ちの回答を保持し、ルーム・参加者・コースの切替では一時的な再生やアニメーションを無効化します。

レース操作の遷移規則は[public/race/lifecycle.js](public/race/lifecycle.js)に集約しています。受付（lobby）から進行（running）、進行と一時停止（paused）の往復、最終以外のコース終了で中間結果（intermission）、次コース開始で進行、終了操作でfinishedへ遷移します。データベース上のrunningには画面のカウントダウン期間も含まれます。リセット・レースの置換・途中終了を、通常のコース完了と混同してはいけません。

無限出題は[server/race/endless.mjs](server/race/endless.mjs)で、不変の教材スナップショット、参加者ごとのシード、コース、回答位置から決定します。クライアントが問題を生成してサーバーに信頼させる構造ではありません。時間の判定と回答受付はサーバーが管理します。

得点と順位は[server/race/grading.mjs](server/race/grading.mjs)と[server/race/rules.mjs](server/race/rules.mjs)に実装しています。現在の得点には、正解点、連続正解、設定で有効な道具の効果が含まれます。正解率を考慮する順位設定では、得点を優先し、同点時に正解率を比較し、同条件は同順位とします。回答速度・到着順は順位決定の基準にしません。学習診断では、自力正解、ヒント使用、復習回答を区別して保持してください。

### 教材・翻訳・画面を変更する場合

[public/shared/curriculum.js](public/shared/curriculum.js)、[server/editor/configuration.mjs](server/editor/configuration.mjs)の教材初期値生成、[docs/content/](docs/content/)の出典記録から確認します。対象単元の単語、意味、画像、録音、例文を照合してください。先生の保存済み編集を新しい初期値で上書きせず、不足している教材設定だけを補います。

共通の問題コントローラーとサーバー検証を使用します。ペア問題は有効な対応の完全な組、並べ替えは有効なトークン識別子を検証します。レースの児童用問題データに正解を含めないでください。複数語の表現や`P.E.`などの句読点処理も維持します。

日本語を初期表示とし、英語の文言も同時に更新して、長いラベルがある両言語のレイアウトを確認します。既存のUI・動作演出・音声の仕組みを再利用してください。BGMは先生用に限定し、動きを減らす設定を尊重します。定期更新で入力欄を作り直さず、画面を離れた際はその画面が所有するタイマーと再生を解除します。

### 検証とリリース管理

Release 79には**回帰テスト92組の通過記録**があります。教材検証は**17設定・387項目**で、旧形式との重複を含むため、異なる単語が387語あるという意味ではありません。過去の35人・授業時間30分の加速シミュレーションでは、30,452リクエスト、レース回答3,209件、再送200件を実行し、予期しないエラーは0件でした。

これらは文書に記載した版とローカル検証環境での結果です。将来のコミット、本番負荷、実機、学校のWi-Fi、描画フレームレートを保証するものではありません。Release 79では教師画面1366×768・1920×1080、児童画面の縦・横・高さが小さい条件を確認しています。[測定値と検証範囲](docs/release-79.md)を参照してください。

動作変更では、不具合を再現し、責務を持つ境界で回帰テストを追加し、関連検証とリリース前の検証を行います。参加→アバター・準備完了→開始→回答・再送→一時停止・再開→コース切替→結果・リセットを通して確認してください。通常練習、両言語、長文、タッチ操作・キーボード操作も確認します。根拠と未検証範囲を記録し、文書だけの変更でリリース番号を変更しないでください。

### 公開環境・データ・担当者交代

公開環境にはWorker、`DB`という名前の永続D1バインディング、ホスティング側の`TEACHER_PASSWORD`シークレットが必要です。`drizzle/`の未適用マイグレーションを順番に適用し、適用済みの状態を管理します。既存データベースに全SQLを無条件で再実行してはいけません。現在の公開先識別情報は`.openai/hosting.json`にありますが、認証情報や所有権移管そのものではありません。

**GitHubのソース、公開アプリ、本番データ、管理アカウントへのアクセスは、それぞれ別の引継ぎ対象です。** GitへのpushだけではWorkerの再公開、データベース移行、開いているブラウザーの更新は行われません。アプリ内の更新確認はGitHub情報と公開済みの版を比較するもので、取得したコードの実行やサーバーへの配置は行いません。

担当者を交代する前に、次を確認します。

1. ホスティング、データベース、ドメイン、リポジトリの管理者を特定し、各サービス側でアクセスを引き継ぎます。秘密情報は非公開の方法で受け渡し、コミットやIssue本文に書きません。
2. 公開中のコミット・画面リリース、公開先識別情報、マイグレーション適用状態を記録します。本番データはデータベース提供側の機能でバックアップし、隔離環境で復元を検証します。
3. 先生が編集した教材・ルール・自作音声を教材JSONで保存し、必要な成績をCSVで出力します。ソースZIPも教材JSONも、本番データベース全体のバックアップではありません。
4. 後任の環境で、専用のデータベース、シークレット、公開先を設定してビルド・検証します。URLが変わる場合は、児童用リンクとQRコードも新しくします。
5. 授業の流れを通して確認し、運用担当を決めます。後任のサービスが準備できてから公開入口とガイドを更新します。

`npm run backup:project`は、**Windows PowerShell用**のソース配布パッケージ作成補助です。依存・ビルド・実行時フォルダーと一部の認証ファイル名を除外しますが、D1のエクスポートや汎用の秘密情報検出は行いません。配布前に中身を確認してください。先生用スターターZIPは入口とガイドのみで、利用には公開サービスが必要です。

### 個人情報・素材の権利・今後の変更

児童の成績、出席番号を含む出力、パスワード、稼働中のデータベースを公開Git履歴に入れないでください。保存された参加認証情報とブラウザーの復帰用データも機密情報として扱います。教材JSONには児童の成績やパスワードを含めません。この境界を変更する場合は文書化してください。

教科書の挿絵、録音、音楽など、同梱する第三者素材の権利は元の権利者に帰属します。ソースの公開は、素材の別途の再配布許諾ではありません。別の学校、教科書、配布方法に広げる前に、権利と出典を確認してください。

構成文書と更新履歴は過去の判断の記録であり、層を追加し続けるための指示ではありません。責務の集約と重複の除去を優先します。不具合、測定済みの性能課題、新しい製品範囲を区別してください。学校別アカウント、新教材、公開方式の変更には、それぞれ設計と移行計画が必要です。
