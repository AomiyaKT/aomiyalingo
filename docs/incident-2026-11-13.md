# 13 November 2026 — hosted startup memory failure

The public homepage, race-teacher page and health endpoint returned the Sites
dispatch HTTP 500 page. Re-publishing the unchanged saved Release 86 artifact
failed with `Script startup exceeded memory limits`. Failed requests did not
reach the application's request handler. Local classroom tests had not exercised
this hosted cold-start validation.

The build previously emitted the entire asset catalogue as eager base64 string
properties in a roughly 49.4 MiB JavaScript module. Emit payloads through lazy
getters instead, keeping only metadata eager. Health checks, HEAD/304 responses
and catalogue validation do not need to instantiate every recording, picture,
font and music string. Existing response decoding, byte budgets, original bytes,
ETags, range handling, curriculum and classroom persistence remain unchanged.

Recovery must be confirmed by a successful hosted startup and direct HTTP checks,
not local tests alone. No database reset or schema migration is involved.

The lazy-payload artifact passed hosted startup validation on 13 November (JST).
Direct checks of the homepage, health, teacher race page, public lesson/race
lookups, client bundle, font, music, recording and vocabulary picture returned
HTTP 200. Checked binary responses matched their original local bytes exactly.

A fresh Node process retained about 53.6 MiB after importing the eager artifact,
versus about 5.2 MiB for the lazy artifact. These are local post-GC measurements,
not Cloudflare isolate telemetry. `tests/worker-startup.test.mjs` prevents a return
to eager media allocation with a <16 MiB import-allocation guard. Do not equate a
passing local test or a prior warm request with successful hosted cold startup.

All 96 regression suites passed after the fix. Read-only production browser checks
in Chrome 157.0.8103.78 and WebKit 26.5 showed the teacher password screen and
successfully played an original recording, with no page-script errors. No teacher
login, student answer submission or classroom-state mutation was used in these
production checks.
